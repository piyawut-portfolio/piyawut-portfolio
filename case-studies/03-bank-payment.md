# เคส 3 — API การเงินและบิลเพย์เมนต์

**บริบท:** 2023–2026 · ผู้เขียนหลักของฮับ Laravel 8  
**สแต็ก:** Laravel 8, Oracle, MySQL, QR, REST แบบ inquiry/confirm

## ปัญหา

ลูกหนี้ใน ERP กับช่องทางจ่ายของธนาคารไม่ลงกันอัตโนมัติ  
ต้องกันจ่ายซ้ำ รองรับหลายช่องทาง และมีไฟล์ภาษีหัก ณ ที่จ่ายตามธนาคารไทย

## สิ่งที่ออกแบบ (ระดับที่พูดในสัมภาษณ์ได้)

- จุดรับแจ้งจากธนาคารสองแห่งแบบ Host-to-Host: ตรวจบิลก่อนจ่าย แล้วยืนยันจ่าย
- ใบ pay-in slip + QR ตามมาตรฐานบิลไทย, ประวัติจ่าย, กฎส่วนต่างเล็กน้อย
- ชุดไฟล์ e-Withholding Tax, ความยินยอม PDPA, สะพานเงินเดือนเข้าสมุดบัญชี

ไม่ใส่ใน Git สาธารณะ: รหัสตอบกลับฉบับสัญญา, biller ID, payload ตัวอย่างจาก UAT จริง

## เดโมที่ทำแทนได้

บริการสมมติ `POST /bills/inquiry` และ `POST /bills/confirm`  
ข้อมูลร้านค้าปลอม, รหัสสถานะที่กำหนดเอง ไม่เลียนแบบสเปกธนาคารทีละฟิลด์
