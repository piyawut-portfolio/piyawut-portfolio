## ปัญหา

ระบบขายภาคสนาม, ERP ใหม่, คลัง, ไฟล์ห้างค้าปลีก และไฟล์สต็อกจากโรงงานอยู่คนละที่  
งานตั้งเวลาและ retry ทำกระจัดกระจาย ฝ่ายปฏิบัติการต้องพึ่งคนไอที

## สิ่งที่ออกแบบ (ไม่ใช่ซอร์สบริษัท)

Modular monolith แยกโดเมนตาม route:

- API สำหรับแอปขาย: ลูกค้า สินค้า สต็อก โปรโมชัน วงเงิน ใบสั่งขาย
- ไพป์ไลน์ใบสั่งขาย: บันทึก → จองสต็อกคลัง → ซิงก์ ERP รายคืน (retry / dry-run / บังคับซิงก์)
- EDI ขาเข้า–ขาออกกับห้างค้าปลีกหลายราย ผ่านตัวกลางเอกสารอิเล็กทรอนิกส์
- รับไฟล์สต็อกจากซัพพลายเออร์หลายราย กฎธุรกิจคนละแบบ (เติมยอด vs แทนที่)
- ส่งออกไฟล์ให้พาร์ทเนอร์คลังจากฐานข้อมูลมรดก
- Job config อยู่ในฐานข้อมูล: เปิด/ปิด, หน้าต่างเวลา, batch, retry

## ผลที่สื่อสารในสัมภาษณ์ได้

- REST กว่า 70 เส้น มีเอกสาร OpenAPI
- งานไฟล์ห้าง/โรงงานลดการยิงมือ
- UAT ขึ้นด้วย Docker + CI ไม่ใช่ copy ไฟล์ขึ้นเซิร์ฟเวอร์อย่างเดียว

## สิ่งที่ **ไม่** เปิดใน Git สาธารณะ

โค้ด, URL ภายใน, สคริปต์ ERP จริง, ไฟล์ EDI จริง, mapping รหัสสินค้าจริง
